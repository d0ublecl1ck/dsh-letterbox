# dsh-letterbox

> 会话级收件箱：Agent 把「你必须知道」的信息投进来，只有你点「已读」才算读过；Agent 回话前先查回执，不再替你假设。

## 它解决什么

主代理带几十个子代理时，子代理的回报是插话式的：一条条冲进主线，你看漏了风险，Agent 也不会知道。它以为你看到了，你以为它没说——两边都基于错误的前提继续往下聊。

dsh-letterbox 给每个会话挂一个收件箱：

1. **Agent 写**：`letterbox_add` 把风险、待你拍板的决定、需要你接手的交接记成一条。
2. **你点已读**：只有面板上的「已读」按钮能把一条标成读过，任何工具都改不了回执。
3. **Agent 查**：`letterbox_status` 在回话前告诉你哪些没被确认；系统提示里写死「没读到的必须点名说明，不许当成已经讨论过」。

## 安装

```sh
dsh plugin --profile <profile> add /absolute/path/to/dsh-letterbox
```

桌面端请在应用自己的「设置 → 插件」里安装，那个 profile 归应用的插件管理器所有。

装完重载窗口（客户端半边）或重启 dsh（宿主半边），侧边栏导航列里出现「收件箱」一项。

## 用法

Agent 侧（模型可见的四个工具）：

| 工具 | 作用 |
| --- | --- |
| `letterbox_add` | 写入一条：`text`（必填）、`kind`（risk / note / decision / handoff）、`priority`（high / normal）、`source`、`scope`（session / global，默认 session）、`options`（可选，1–6 个候选，每个去空白后 ≤60 字，重复项自动去掉） |
| `letterbox_list` | 列出当前会话的条目与回执，可只列未读 |
| `letterbox_status` | 回话前核对：还有几条没被确认 |
| `letterbox_answer` | 读人工在卡片上给出的答复：选项、一句话回复与答复时间；只读，永远不写回执或答复 |

人这一侧：侧边栏导航列里有一项「收件箱」（inbox 图标，排在「自动化任务」之后）：点击把主区切到整页收件箱（铺满主区，无遮罩，选别的导航项即离开）。入口只有侧边栏这一处，收件箱本身不再有浮层。入口图标上叠两个未读角标：右上蓝色是**本会话**未读，左下橙色是**全局**箱未读；1–99 原样显示，超过 99 显示 `99+`，计数为 0 时那个角标不渲染，鼠标停在角标上能看到「本会话 N 条未读 / 全局 N 条未读」。角标每 5 秒取一次 `/letterbox/list`，一次请求同时拿到两个数；请求失败时保留上一次的数字，不会闪成 0，也不会在侧栏里报错。

收件箱渲染的是同一套 Gmail 式界面：顶部一条「收件箱 + 未读总数」，下面左边是**标签栏**（宽 176px，分「会话」与「全局」两组，每组各有带数量的「未读」和不带数量的「历史」，整行可点、选中浅底加粗；窄屏 <720px 时折成上方一排横向标签），右边是列表区。列表区顶部只有一行工具栏：全选勾选框 + 当前标签名（如「会话 · 未读」）+ 右侧窗口计数（如「1–20 / 52」）；搜索框只在「历史」标签下出现。

列表每行约 44px：左侧勾选框、未读圆点（已读只留空位）、kind 小徽标，中间是加粗（未读）/ 常规（已读）的正文首行加一行灰色摘要，右侧是时间（当天 HH:MM，更早 MM/DD）；悬停整行浅底，并在右侧浮出「标记为已读」勾按钮（点它不会打开这条）。点击行（或聚焦后 Enter / Space）切到同一面板内的详情：顶部条只留「← 返回」，正文下方单独一条操作行（上边一条细线分隔）依次是「标记为已读」（只对未读条目出现，带勾图标）·「上一封」·「下一封」，列表首条禁用「上一封」、末条禁用「下一封」；再往下是 14px/1.7、可选中复制的正文与「类型 / 优先级 / 来源 / 创建 / 已读」两列灰字段。详情打开时列表隐藏，Esc 或返回先回列表，并恢复离开时的列表滚动位置。

勾选任意行后列表上方出现「已选 N 项 · 标记为已读 · 取消选择」，工具栏的全选框即全选本页，操作是逐条串行调用、单条失败不阻断，完成后清空选择并重取当前页。分页是 Gmail 式的：底部左右「较新 / 较旧」两个幽灵按钮，中间「第 X–Y 条，共 N 条」，第一页禁用「较新」、最后一页禁用「较旧」，每页 20。

主列表只放未读，点过已读的那条立刻离开。

**常驻卡组**：右侧主内容区的左下角（侧栏右缘之后、输入框上方 12px）常驻一组卡片，本会话每一条没处理过的笔记都在里面——窗口重载后旧的未读照样出现，新到的继续追加，全局箱的条目不出卡片。只有 1 条时不叠，直接摊开完整卡片；2 条轻度叠放（第二张露 3px、透明度 0.9）；3 条及以上只叠 3 张（新在上，逐张错开 3px，透明度依次 1 / 0.9 / 0.8），其余收成叠放组右上角的「还有 N 条」角标，点它跳到收件箱的未读列表。

鼠标在卡片组上停 120ms 才展开成纵向列表（扫过不会闪），指针离开 200ms 后才收起。展开后每张卡片按自己的内容高度排布、正文完整显示，列表从上到下就是新到旧，最多 8 张，多出来的在末尾折成一行「还有 N 条」；列表最高 60vh，超出在列表内部滚动，不会顶出窗口。点卡片、用 Tab 进入卡片组、或开始回复都会把列表钉住（触屏和键盘没有 hover，这是它们的入口），钉住之后指针移开也不再收起；Esc 或点卡片组外部取消钉住并收起。

卡片不自动消失：只有处理动作才让它离开——点「已读」标记（和面板里的已读是同一个回执）、对带选项的条目点选项按钮、点「回复」就地展开单行输入（回车或「发送」）。这三个动作都是**乐观更新**：卡片立刻离开、请求在后台发；宿主拒绝时卡片回到原位，并在组内显示一行错误。卡片上只有这三类按钮，没有单独的「展开 / 收起」；卡片主体可以用 Tab 聚焦、Enter / Space 切换展开。未读数量变化时会有一条视觉隐藏的 aria-live 播报（「共 N 条未读」或「新增 N 条未读」），不逐卡播报。叠放切列表只做 120ms 淡入，不做高度动画；`prefers-reduced-motion` 下直接切换、不播动画。

历史 tab 收所有已读条目，同样按上面的「较新 / 较旧」翻页（每页 20）：顶部显示「共 N 条」，搜索框按正文 / 来源 / 类型做不区分大小写的匹配（输入停 250ms 后查询）；结果只读，行上不再有「标记为已读」。

空箱时入口同样在，文案跟着当前标签走：会话未读「没有未读」、会话历史「还没有历史」、全局未读「全局没有未读」、全局历史「全局没有历史」、搜索无果「没有匹配的历史」，按钮不会消失。

### 两个箱子：会话 / 全局

- 每条笔记有 `scope`：`session`（默认）只属于当前会话；`global` 放进跨会话共享的全局箱。
- 只有用户明确说「发到全局 / 全局记一下」，或该事实明显不绑定当前任务（长期偏好、跨会话知识、通用规则），才用 `global`；其余一律 `session`。
- 左侧标签栏分「会话 / 全局」两组，两个箱子的未读、历史、搜索、分页各自独立；未读数量直接标在标签上，全局未读不计入「漏核对」（漏核对只按会话未读记账）。

Agent 侧有两条硬约定：宿主每轮都会在系统提示里注入一行 `Letterbox:` 回执，Agent 照它行动——有未读时必须调用 `letterbox_status` 并逐条点名（漏一轮记一次 miss），没有未读时不必查；每轮里「人必须知悉」的事要用 `letterbox_add` 发进收件箱，不能只写在回复正文里。

当所有条目都被点过已读，注入的那行会说「the human has acknowledged all N filed note(s)」：Agent 视它们为双方共享的知识背景，从这些结论说话，不再重复解释，也不问「你看到了吗」。

## 数据在哪

`$DSH_HOME/letterbox.json`，按 `sessionId` 分区。写入是「临时文件 + rename」，重启不丢。

## 配置

在 profile 的 `cordis.patch.yml` 里覆盖 `letterbox` 这一行（patch 会替换整块 config，想保留的字段要重述）：

```yaml
- id: letterbox
  config:
    enabled: true
    requireCheckBeforeReply: true
    maxItemsPerSession: 200
```

| 字段 | 默认 | 含义 |
| --- | --- | --- |
| `enabled` | `true` | 关掉后不注册工具、不注入提示词 |
| `requireCheckBeforeReply` | `true` | 提示词里把「有未读就必须查」写成硬要求；关掉后只说「注入的回执有未读时再查」 |
| `enforcement` | `strict` | `strict` 时有未读、本轮却没调用 `letterbox_status` 的正常回合记一次 miss；没有未读的回合不记。`warn` 只提示不记账 |
| `maxItemsPerSession` | `200` | 单会话上限，超出时先丢最旧的已读条目 |

### 核对（checkpoint）与漏检记账

- `letterbox_status` 不只是查询：它会把「本轮查过了」写进会话账本（`checkedAt` / `checkedTurn`），客户端据此显示「上次核对 HH:MM」。
- 每个 `turn/start` 由宿主生成一个 turn id；`turn/end` 若是正常完成、仍有未读、且本轮没调用过 `letterbox_status`，就记一次 miss（`misses` 累加），面板显示「Agent 漏核对 N 轮」。没有未读的回合不记。
- 每轮宿主还会往 Agent 的系统提示里注入一行 `Letterbox:` 回执，按当前账本三选一：有未读（要求查并点名）、全部已读（不必查，视为共同背景）、本会话还没有条目（提示用 `letterbox_add` 写入）。它逐 Agent 注册、每轮装配时求值，所以永远反映此刻的账本。
- 这是宿主侧事实，不依赖模型自述；中断/取消的回合不计 miss。

## 边界

- 它不是通知中心：没有桌面通知、没有声音，只有侧栏入口上的未读角标、主内容区左下角的常驻卡片组与整页收件箱。
- 它不是待办清单：条目的生命周期是「未读 → 已读」，没有完成态。
- 回执只能由人写入：工具侧没有 `letterbox_mark_read`，这是设计约束，不是遗漏。
- 目前只做单会话维度；跨会话汇总留给别的插件。
